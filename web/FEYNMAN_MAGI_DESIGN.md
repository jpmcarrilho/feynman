## Vision & Problem Statement
Currently, student learning and government policy evaluation are both broken in distinct ways:
1. **Static Learning**: Reading economic PDFs and textbook slides is dry. Traditional office hours are heavily bottlenecked.
2. **Ideological Policy-Making**: Macroeconomic policies are debated with political bias rather than empirical, micro-level simulations of citizen behaviors.

This project outlines two powerful pathways built on top of the **Feynman Study Hub** core infrastructure (Next.js, Prisma, and Gemini live voice APIs) to solve these problems by making education open/shareable or by transforming economics into a physics-like simulation.

---

## Path A: The Shareable Course Workspace (SaaS & Dev Community Tool)
Transform the hardcoded DEDP study app into a generic, plug-and-play course engine where teachers or students can create interactive classrooms instantly.

### Core Features
- **Syllabus / Course Ingestion**: Teachers upload lecture notes, slides (PDF), or syllabus links. The pipeline (`web/src/services/ingest.ts`) auto-segments the content into the SQLite/Prisma `Course`, `Topic`, and `Exercise` schema.
- **Feynman Voice Tutor on Demand**: Automatically configures the `useLiveAPI` Gemini model context to use the ingested lectures as ground truth.
- **Shareable Links**: Generates a shareable workspace link (e.g., `/c/mit-14-750x-week-1`) containing flashcards, lectures, and interactive tutor logs.
- **Self-Hosting Deploy Button**: A single "Deploy to Vercel" button on the GitHub readme that copies the repo, configures the Prisma SQLite DB, and starts the service instantly.

### Technical Trajectory
- **Effort**: Medium (M)
- **Risk**: Low (Low competition in developer-hosted niche)
- **Pros**:
  - Immediate, practical utility for student study groups and teachers globally.
  - Organic growth loops: students share course links with peers.
- **Cons**:
  - Selling directly to universities is slow; must rely on bottom-up developer/student adoption.

## Path B: The Macro Policy World Model ("MAGI")
An empirical policy simulation sandbox where users submit any tax, labor, or spending proposal and watch simulated demographic agents react, debate, and change macroeconomic indicators.

### Core Features
- **50 Multi-Demographic AI Agents**: Personas generated using real census data (e.g., IBGE in Brazil), mapping income brackets, regional leanings, and industry sectors.
- **Micro-to-Macro Engine**: Agents read the user's submitted policy and run standard economic equations (Utility Functions, Labor-Leisure trade-offs) to adjust their simulated output.
- **The Debate Arena**: Agents form localized factions and debate each other live in the Next.js UI using `useLiveAPI` or chat streams.
- **National Indicators Dashboard**: Live chart updates tracking:
  - **Gini Coefficient** (Inequality index)
  - **GDP Growth**
  - **Simulated Inflation & Government Balance Sheet**
  - **Aggregate Approval / Persuasion Score**

### Technical Trajectory
- **Effort**: Extra Large (XL)
- **Risk**: Medium (Requires solving rate limits and multi-agent consensus)
- **Pros**:
  - Genuinely pioneering R&D with massive viral potential.
  - Bypasses copyright hurdles by using standard econometric formulas and public census variables.
- **Cons**:
  - High concurrency overhead; requires queuing and smart model selection (e.g. `gemini-1.5-flash` or `gemini-2.0-flash` for agent reasoning).

## The Multiplier: GraphRAG Ingestion Pipeline (Unified Core)
You hit on an incredibly deep architectural truth during our session: **The data ingestion pipeline is the absolute core multiplier.**

Whether building a Classroom Study Assistant or a Policy World Model, you need a way to insert knowledge dynamically, map relationships between concepts, and ground AI responses with high-fidelity, hallucination-free facts.

### The GraphRAG Architecture
Instead of standard chunk-and-vector retrieval, we can construct a lightweight **GraphRAG Ingestion Pipeline** directly in `web/src/services/ingest.ts` using Gemini:
1. **Extraction**: When a document (PDF, lecture slide, census profile, or economic study) is uploaded, we prompt `gemini-2.5-pro` (via structured outputs `generateObject`) to extract key **entities** (e.g., "RCTs", "Gini Coefficient", "Isoelastic Utility", "Brazil 2026 Tax Reform") and **relationships** (e.g., "Wealth Tax -> *risk of* -> Capital Flight", "Randomized Control Trials -> *verifies* -> Policy Efficacy").
2. **Schema Extension**: We extend SQLite with two tables:
   - `ConceptNode`: Represents core concepts, parameters, or policies.
   - `ConceptEdge`: Represents directed relations between those concepts with semantic metadata.
3. **Retrieval (GraphRAG Context)**: When the Voice Tutor in `VoiceHub` or an agent in the `MAGI Arena` debates a topic, we query the graph to extract the **neighboring nodes** of their discussion. 
   - *Example*: If the student asks about a "wealth tax," the system automatically retrieves not just text matches for "wealth tax," but also the connected concepts: "Capital Flight," "Tax Elasticity," and "Laffer Curve" models.

This completely solves copyright and factual accuracy barriers by grounding the simulation in a rigorous, mathematical, and verified knowledge graph.

## Technical Feasibility & Reusability
The current codebase has major architectural primitives we can leverage:
1. **`prisma/schema.prisma`**: The schema already models courses, topics, and exercises. It can be easily extended with an `Agent` and `PolicySimulation` table.
2. **`web/src/components/features/SideVisualizer.tsx`**: Can be reused as the live debate stream / agent-log visualizer.
3. **`web/src/components/features/VoiceHub.tsx`**: Can act as the bridge where the user speaks *directly* into the world model to propose or argue policy changes, receiving voice feedback from agent factions.
